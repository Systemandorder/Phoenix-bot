# 🔥 Phoenix

Тут пояснено, що робить кожен файл і як ними користуватись. Усе написано простими словами.

## Як усе працює разом

Спочатку програма читає налаштування з файлу `.env`. Потім функція `build_core` створює один набір сервісів, а саме базу, права, шифрування і журнал. Кожен сервіс отримує те, що йому потрібно, і більше ні від чого не залежить.

```python
from phoenix.config import get_settings
from phoenix.core.bootstrap import build_core

core = build_core(get_settings())
tier = core.access.get_tier(user_id, profile)
ok = core.access.can_access_file("tasks/lab5.pdf", "ФБ-56", user_id)
core.audit.log(user_id, "open_file", "tasks/lab5.pdf")
core.close()
```

## config.py

Єдине місце, де читаються налаштування. Функція `get_settings()` повертає готовий і незмінний набір значень. Якщо обов'язкове значення пропущене або хибне, програма одразу зупиняється з чітким повідомленням, наприклад що ключ шифрування некоректний. Токен і ключі приховані, тому в журнали не потрапляють.

## core/db.py

Єдиний вхід у базу SQLite. Клас `Database` створює одне зʼєднання на кожен потік і вмикає режим WAL, перевірку звʼязків між таблицями та очікування, якщо база зайнята.

Основні методи такі.

* `execute` виконує команду
* `query_one` повертає один рядок
* `query_all` повертає всі рядки
* `tx` відкриває безпечну транзакцію, яка або виконується вся, або відкочується вся
* `backup_to` робить узгоджену копію бази, поки бот працює
* `close` закриває всі зʼєднання
* `aexecute`, `aquery_one` і `aquery_all` роблять те саме, але не блокують бота

## core/kv.py

Прості налаштування за принципом ключ і значення. Вони зберігаються в старій таблиці `bot_settings`. Методи `get`, `set`, `set_if_absent`, `delete`, `exists` і `with_prefix` покривають усе потрібне. Запис робиться за одну дію, тому ключ ніколи не зникає посередині. Клас `Keys` збирає всі формати ключів в одному місці, тож помилитись у назві неможливо.

## core/crypto.py

Клас `KeyVault` дає кожному користувачеві власний ключ шифрування. Методи `encrypt` і `decrypt` працюють з байтами. Якщо увімкнути режим захисту, ключі користувачів зберігаються зашифрованими головним ключем. Коли ключ не підходить, повертається зрозуміла помилка `KeyVaultError`.

## core/access.py

Тут живуть рівні користувачів і права на файли.

* `Tier` описує рівні доступу
* `get_tier` визначає рівень користувача
* `can_access_file` каже, чи можна відкрити файл, і при будь-якій помилці відповідає ні
* `set_owner` призначає власників файлу
* `path_uid` перетворює шлях на короткий код
* `ProfileService` читає і запамʼятовує профілі користувачів

Спроби вийти за межі папки, зокрема з двома крапками і зворотними слешами, блокуються.

## core/audit.py

Клас `AuditLog` записує в таблицю, хто і що зробив. Метод `log` працює одразу, а `alog` не блокує бота.

## core/migrations.py

Функція `migrate` приводить базу до потрібної версії. Перед змінами вона робить резервну копію. Якщо база новіша за код, вона відмовляється працювати, щоб нічого не зіпсувати. Файл `schema_legacy.sql` містить точну схему всіх таблиць старого бота.

## core/bootstrap.py

Функція `build_core` збирає все разом і повертає обʼєкт `Core` з полями `settings`, `db`, `kv`, `vault`, `audit`, `access` і `profiles`. Метод `close` закриває базу при вимкненні.

## logging_setup.py

Функція `setup_logging` налаштовує журнали. Фільтр `RedactFilter` автоматично ховає токени та паролі.

## scripts

* `check_db.py` пробує всі міграції на копії справжньої бази і перевіряє, що дані не загубились
* `schema_report.py` показує таблиці й кількість рядків без самих даних
* `schema_dump.py` зберігає точну схему бази у файл

## Налаштування

Усі значення задаються у файлі `.env`. Обов'язкові три, це `BOT_TOKEN`, `ADMIN_ID` і `MASTER_KEY`. Решта описані у файлі `.env.example`.
